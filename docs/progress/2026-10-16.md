## Done today

### Matching the backend
- `Recipe` type matches the API: `authorName`, `bSaved` and `savedCount` added, and `savedBy` and `image` removed. `authorId` can be `null`. Types live in `types/recipe.ts`.
- Error codes map to friendly text in one place: `helpers/errors.ts` (`getErrorMessage`, `getErrorCode`, `getFieldErrors` for `Validation_Error`, and `isSessionEnded`).
- `Routes.REGISTER` (`/register`) became `Routes.SIGN_UP` (`/sign-up`) to match the page.

### Auth
- Login and sign-up pages call the API, check the same rules as the backend, and show errors.
- The token is kept in an `authToken` cookie (`helpers/auth.ts`), so `middleware.ts` can protect pages before they render. Logged out, only the auth pages are reachable. Logged in, the auth pages redirect home. `?redirect=` returns to the page you came from, and only allows paths on this site.
- The axios interceptor sends the token as `Authorization: Bearer`. The API ignores cookies.
- When the session ends (invalid or expired token, password changed, user deleted), the browser logs out. On the server, pages redirect to `/logout` (`app/logout/route.ts`), which clears the cookie.
- Logged-in pages are in `app/(main)/` with the nav shell. Auth pages are in `app/(auth)/` without it.

### Server-side data
- `helpers/serverApi.ts` (`server-only`): `getSession()` reads the user id from the token, and `serverGet()` calls the shared axios instance with the token header.
- **My Recipes** (`/my-recipes`) is a server component. Pagination is links to `?page=N`, and `loading.tsx` and `error.tsx` handle loading and failures. It has a "Create recipe" button, and the card is `components/RecipeCard`.
- **View recipe** (`/my-recipes/[id]`) fetches on the server and shows everything:
  - category, author, saved count, private and suggestions badges
  - personal-edit notices with "View the original" (`?original=true`), and a notice for recipes whose author deleted them
  - description, times, ingredients grouped by heading, numbered steps, tags
  - `not-found.tsx` for missing, hidden or malformed ids, and `error.tsx` for anything else

### Create recipe (`/my-recipes/new`)
- `components/RecipeForm` is reusable: give it `initialValues`, a `submitLabel` and an `onSubmit`, and it shows API errors itself, including field errors mapped to the right row.
- Ingredients can have **headings**. The form edits one flat list of headings and ingredients (`rows.ts`). On save, each ingredient gets the nearest heading above it as `subheader`. `rowsFromIngredients` converts back, ready for the edit page.
- **Keyboard-first:** Tab or Enter at the end of a row adds the next one, Tab skips delete and drag buttons, Backspace removes an empty row, and Alt+↑/↓ moves the current row.
- **Drag and drop** with dnd-kit. Dragging a heading collapses the groups and moves the heading's whole group as a block.
- **Units:** you can type into the unit field (`g` → g, `tb` → tbsp), and Tab picks the match.
- **Tags:** autocomplete from `GET /recipes/tags`, with the top match highlighted. Tab takes the suggestion and Enter adds exactly what you typed. Tags are cleaned up the way the API stores them, with a limit of 10 tags of up to 30 characters (`helpers/tags.ts`).
- The form also checks the backend's real rules from its Zod schema, which go further than `docs/API.md`: description is required, and serves and times must be whole numbers above 0. Completely empty rows are ignored on save.

### Test setup
- The shared test render (`test-utils/render.tsx`) uses Mantine's `env="test"`, so dropdowns open instantly and in place.
- Jest maps `@/…` paths and treats `server-only` as an empty module.

## Decisions to remember
- **Dragging a heading moves its whole group.** Moving only the heading line was rejected as unexpected.
- **Enter in the tags field adds exactly what was typed.** Tab or the arrow keys take a suggestion. Users must never be forced into a suggestion.
- **Tags display in lowercase**, exactly as stored. This is easy to change to display-only capitalisation.
- **After creating a recipe** the form goes to My Recipes. Switch it to the new recipe's page now that the page exists.

## Open questions
- **Prep and cook time of 0.** The backend requires both to be above 0, so cocktails and no-cook recipes can't be saved with 0 minutes. The recipe card already hides times of 0, which suggests 0 was meant to be allowed. If so, change `.positive()` to `.nonnegative()` in the backend's `RecipeSchema` (with tests and an `API.md` update), then relax `recipeFormSchema.ts`.

## Next steps

Pick up here, roughly in this order. Check `../my-recipe-book/docs/API.md` for each endpoint's body and errors.

1. **Commit the recipe view page** (currently uncommitted).
2. **Save and unsave** from the recipe page with `POST /recipes/toggle-save`. If the user has personal edits, the API refuses with `CONFIRM_LOSE_EDITS`: show a warning, then resend with `bConfirmLoseEdits: true`. This needs a small client component for the button, then `router.refresh()`.
3. **Reset personal edits** with `POST /recipes/reset-edit`, shown next to the "View the original" notice when `bHasEdits` is true.
4. **Edit own recipe** with `PATCH /recipes/update-own-recipe`. Reuse `RecipeForm` with `initialValues` built using `rowsFromIngredients`. Only show it when `recipe.authorId` is the current user and `authorName` isn't `null`.
5. **Delete own recipe** with `POST /recipes/delete`, behind a confirmation. Mention that people who saved it keep a copy.
6. **Personal edit** for savers with `POST /recipes/edit-recipe`. This changes ingredients, steps and tags for themselves only, and can reuse the ingredient, step and tag parts of `RecipeForm`.
7. **Suggestions**:
   - Savers can suggest changes when `bAllowSuggestions` is true and the recipe has an author (`POST /recipes/edit-recipe` with `isSuggestion`).
   - Authors review them with `GET /recipes/view-suggestions/:id` and `POST /recipes/review-suggestion`.
   - Users see their own with `GET /recipes/my-suggestions`.
8. **Saved recipes list**: `GET /recipes/search?bOnlySaved=true`. Reuse the My Recipes page pieces (`RecipeCard`, `RecipePagination`).
